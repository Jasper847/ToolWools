Frequently Asked Questions

What is a JSON Web Token (JWT)?

A JSON Web Token (JWT) is an open standard (RFC-7519) that defines a compact and self-contained way for securely transmitting information between parties as a JSON object. Since the token is digitally signed, the recipient can trust the claims integrity and verify that the content has not been altered during transit.

Does this decoder verify JWT cryptographic signatures?

No. This tool parses the token structure and displays the JSON components for inspection purposes only. In a real-world application, your server must verify the signature using the private secret key (for symmetric HS256) or public key certificate (for asymmetric RS256/ES256) to ensure the token remains cryptographically trusted.

How are headers, payloads, and signatures separated?

A JWT string consists of three distinct parts separated by dot characters (.): the **Header** (defines the algorithm type and format), the **Payload** (contains session claims, expiry, and custom data fields), and the **Signature** (verifies payload tampering). Each of these parts is individually encoded using the Base64Url algorithm.

How does the decoder handle token expiry timestamps?

Standard JWT claims use Unix Epoch timestamps (seconds since January 1, 1970) for dates like Expiry (exp), Issued At (iat), and Not Before (nbf). Our decoder automatically reads these numerical timestamps and translates them into human-readable local times inside the claims summary section.

Is it secure to paste my application tokens here?

Yes. All parsing and Base64Url decoding logic is executed client-side in your local browser sandbox. No input strings are sent to our backend servers, ensuring your access tokens, usernames, and payload claims are never intercepted or logged.

The Structure of JSON Web Tokens

JWTs are encoded using **Base64Url** representation rather than standard Base64. Base64Url replaces standard characters that are illegal in URL pathways: it swaps + with -, replaces / with _, and removes the trailing padding = signs. This allows tokens to be safely passed in HTTP authorization headers, query strings, or cookies without requiring URL character escaping.

A typical signature calculation signature follows this pattern: Algorithm(Base64UrlHeader + "." + Base64UrlPayload, secretKey), preventing any user-side modification of the payload claims without invalidating the verification key checksum.

Security Tip: Never include sensitive client credentials (like raw passwords, database strings, or API secrets) in your JWT payloads. Payload claims are public-readable to anyone who intercepts the token.
